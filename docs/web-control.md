# Webコントロール

Windowsサービス内のHTTPS管理画面です。プロキシーの待受（初期3128）と管理Web（初期3129）は別ポートです。Web管理は初期状態で無効、パスワードも未設定です。GUIを閉じてもサービスが動いていれば利用できます。

## 初回設定と更新

1. 新EXEで管理GUIを起動します。旧GUIがトレイにいる場合は「GUIを終了」してから開いてください。
2. 既存環境はサービスを停止し、「サービスのプログラムを更新」を実行します。Web機能とFirewall再同期タスクの登録には本体更新が必要です。
3. 「設定・サービス」→「Webコントロール（HTTPS）」で「Webコントロールを有効」にチェックし、ポート（初期3129）と5～256文字のパスワードを指定して「Web設定を保存」を押します。英数字の混在や記号は必須ではありません。サービス停止中でも保存でき、次回開始時に反映します。稼働中の有効化・無効化・ポート変更・パスワード変更はプロキシー通信を止めず反映します。
4. クライアントから `https://サーバーのIP:3129/` を開いてログインします。設定欄に現在の接続先と証明書のSHA-256指紋を表示します。GUIの「管理Webを開く」は同じPCのlocalhostを開きます。

管理WebへはLAN内で直接接続してください。ブラウザーでWhiteProxyをプロキシーとして設定している場合は、管理先のIP/PC名をプロキシー除外一覧へ追加します。管理ポートへのCONNECT中継を許可する必要はありません。

パスワード欄が空なら既存のパスワードを維持します。変更すると全Webセッションが無効になります。認証済みセッションとCookieはログインから24時間で失効します。明示的なログアウト、Web設定変更、サービス再起動でも失効します。パスワードを忘れた場合はサーバーの管理GUIから再設定してください。

## HTTPS証明書

初回有効化時に自己署名証明書を生成し、`%ProgramData%\WhiteProxy\web-control.pfx` に保存します。localhost、PC名、生成時に割り当てられたIPv4をSANに含めます。秘密鍵を含むPFXはクライアントへ渡さないでください。

自己署名証明書を信頼していないクライアントでは証明書警告が出ます。「公開証明書を書き出す」で `.cer` を出力し、設定画面のSHA-256指紋を別経路で照合してください。書き出し完了時にも登録手順を表示します。Windowsではブラウザーを使うクライアントPCでCERファイルを開き、「証明書のインストール」→「ローカルコンピューター」（管理者権限）→「証明書をすべて次のストアに配置する」→「信頼されたルート証明機関」を選択します。完了後はブラウザーをすべて終了して起動し直してください。接続には証明書に含まれるPC名またはIPを使用します。IP変更でSANにないIPになった場合はPC名を使用するか、管理者がサービス停止後にPFXを更新してください。組織発行証明書を利用する場合も、秘密鍵付き・パスワードなしPFXをこの保護済みパスへ配置し、サービスを再起動します。

有効期限は3年です。起動時に残り7日以下の場合は再生成するため、その場合は指紋とクライアントの信頼設定を更新してください。

## 操作

- ダッシュボード：端末IP/CIDRとサービスをまとめたルールの追加・編集・削除、曜日/時間帯、一時許可・予約・終了、一時遮断、Clone、上下移動、全遮断・解除。
- 許可サービス：サービスの追加・編集・削除・無効化、1行1件のホスト、TCPポート、サービスセットJSONの取込・出力。`*.example.com` は親ホストを含みません。
- 通信・監査ログ：直近1,000件の取得、端末/ホスト/パス/理由の検索、許可/拒否/監査・日付の絞込、CSV出力、拒否ホストの追加。HTTPS通信のパスはTLS非復号のため取得できません。

GUIとWebは同じ検証・適用・ロールバック処理を使用します。編集中に別の操作で設定が変わった場合は保存を拒否し、編集内容を画面に残します。Webからプロキシーの待受IP/ポートやWindowsサービスの停止・更新は変更できません。稼働状態に問題がある場合も、管理GUIで復旧できます。

一時許可の履歴を参照する端末・サービスは削除できない場合があります。その場合はサービスを無効化してください。無効化も既存接続に反映します。

## Firewallと権限

Web管理を有効にして保存すると、アプリ固有の `WhiteProxy-Web-Control` 受信規則を追加・更新します。対象は配置済みEXE・管理TCPポート・ローカルサブネット・Domain/Privateです。Publicには自動開放しません。無効化・サービス登録削除時にはこの規則を削除します。ルーターのポート転送やインターネット向けの公開は設定しません。

別VLANの管理端末から利用する場合は、ルーターの通信許可と、管理端末のIPを明示したWindows Firewallの追加規則が必要です。[導入・操作ガイドのWebコントロール](user-guide.md#7-webコントロール) に設定例があります。手動追加した規則はアプリの自動削除対象ではありません。

プロキシー側の受信規則は従来どおり登録端末のIP/CIDRに限定します。Webから端末を追加・変更したときは、NetworkServiceが固定の `WhiteProxy Firewall Sync` タスクへ再同期を要求します。タスクはSYSTEMで保護済みEXEの固定引数 `--sync-firewall` のみを実行し、保護済み設定からアプリ固有の2規則を再同期します。NetworkServiceにはこのタスクの読取り/実行だけを許可し、EXE・引数の変更権限は与えません。失敗した設定適用は元の設定へロールバックし、通信を遮断します。

Webを利用する人は共通パスワードで管理者権限相当のアプリ操作を行います。Windows管理者権限の付与ではありません。TLS・Secure/HttpOnly/SameSite=Strict Cookie・CSRFトークン・Origin確認・ログイン試行制限を使用し、パスワードはソルト付きPBKDF2ハッシュのみ保存します。パスワード・Cookieは監査ログへ出力しません。監査主体はWeb管理者と接続元IPです。

## 初期サービス

初期値は `Defaults/WindowsUpdate.services.json` に同梱したWindows Update 1件です。ユーザー提供の `WhiteProxy-WindowUpdateservices.json` の20ホスト・80/443・出典・定義バージョン・注記を保持しています。既存設定は移行時に上書きしません。初期サービスが存在しても、端末・有効な許可ルールがなければ通信は拒否します。
