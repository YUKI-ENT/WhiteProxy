# WhiteProxy 開発・運用詳細

利用者向けの手順は [導入・操作ガイド](user-guide.md) を参照してください。以下のビルド・発行コマンドは、リポジトリのルートで実行します。

C# / .NET 10 の日本語 Windows Forms 管理GUIと、独立したWindowsサービスで動くホワイトリスト式HTTP/HTTPS明示プロキシーです。TLSは復号しません。端末IPv4 × サービス × 常時許可・曜日別予定表・一時開放で制御し、期限切れ時は既存接続も切断します。

仕様の `WhiteListProxy` は本実装では **WhiteProxy** に統一しました。ユーザー指定を優先し、インストーラーは作成せず **自己完結の単一 `WhiteProxy.exe`** を発行します。同じEXEをGUIとサービスの別プロセスとして使用します。

## Visual Studioで編集・ビルド

1. .NET 10対応のVisual Studio（2026以降）と「.NET デスクトップ開発」を用意します。手元では.NET SDK 10.0.401で確認しています。
2. `WhiteProxy.sln` を開きます。
3. `WhiteProxy.Admin` をスタートアッププロジェクトに設定します。共有起動プロファイル `WhiteProxy 管理GUI` もあります。
4. F5でGUI、Ctrl+Shift+Bでソリューションをビルドします。GUIのデバッグにはVisual Studio自体を「管理者として実行」で起動してください。発行EXEは起動時にUACで昇格し、すべての管理操作を同じ権限で行います。

```powershell
dotnet build WhiteProxy.sln
dotnet test WhiteProxy.sln
```

画面はコードで構築しています。`MainForm.cs` / `RuleEditor.cs` / `Editors.cs` をVisual Studioで編集できます。WinFormsデザイナーによる画面編集は使用していません。ドメイン判定と通信本体のテストは `dotnet test tests/WhiteProxy.Tests` でLinuxでも実行できます。Windows固有テストは別プロジェクトです。

## 単一ファイル発行

Visual Studioで `WhiteProxy.Admin` を右クリック →「発行」→ `Portable-win-x64` を選択します。または次を実行します。

```powershell
./publish.ps1
# または
dotnet publish src/WhiteProxy.Admin -p:PublishProfile=Portable-win-x64
```

出力: `artifacts/publish/win-x64/WhiteProxy.exe`。このEXEだけを配布できます。.NETの別インストールは不要です。WinFormsを使用するためトリミングは無効、ランタイム・依存ライブラリ・ライセンス表示をEXEへ同梱します。ネイティブランタイムは起動時にWindowsの一時領域へ展開されます。「単一ファイル」は配布形式であり、設定やログは別途保存します。

## 初回の使い方

1. 発行した `WhiteProxy.exe` を起動し、起動時のUACを許可します。管理GUIは管理者権限に統一しています。初回は「サービス未接続」が正常です。
2. 「設定・サービス」の **「初期設定・登録管理」** にある「初回登録して開始」を押し、UACを許可します。このボタンは未登録のときだけ表示します。EXEを `%ProgramFiles%\WhiteProxy\WhiteProxy.exe` へコピーし、NetworkServiceで自動起動するWindowsサービスを登録・開始します。インストーラーは不要です。
3. 実際のサービス起動とGUI接続を確認してから完了します。画面の「GUIとの接続: 接続済み」を確認してください。未登録・停止中・起動エラーは同じ画面に表示します。既に登録済みなら「開始」も使用できます。設定・ログは `%ProgramData%\WhiteProxy\` に作成されます。
4. 「許可サービス」で接続先ホストを確認してから、ダッシュボードの「許可ルールを追加」で対象端末IP/CIDR・サービス・許可時間をまとめて設定します。起動時に昇格済みなので、開始・停止・端末追加・ルール追加の途中で再昇格する操作はありません。各編集画面の **「保存」** で検証・保存・反映まで完了します。保存エラー時は入力内容を画面に残します。未登録端末・未知ホスト・空のホスト一覧は拒否します。
5. 新規ルールの初期値は「一時許可のみ」で、保存だけでは開通しません。通常の許可時間は「全日・24時間」「曜日・時間帯」に変更できます。ダッシュボードでルールを選択し、各行の「一時許可」フォームで新規・延長・終了を行います。理由の入力は不要です。操作の選択は横並びのトグルボタンです。既存枠は延長として統合し、監査記録を残します。初期上限4時間、管理者が最大24時間まで設定できます。

ダッシュボードは開放中を緑、遮断中を赤、サービス未接続・異常時を状態未確認として灰色で表示します。「一時遮断」は解除するまで全日許可・予定表・一時許可より優先します。各行の「一時遮断」フォームで遮断・解除を行います。解除は元の予定と有効期限内の一時許可へ戻す操作です。ルール編集に「明示拒否」チェックはありません。既存の明示拒否は手動遮断として保持します。一時許可だけで存在する旧設定も一覧へ表示します。
IP/CIDRの同一・重複指定ができます。送信元IPと接続先サービスが一致するルールを上から調べ、最初の有効な許可または明示的な一時遮断を適用します。時間外のルールは下位へ進みます。`/24`遮断の例外として`/32`を許可する場合、`/32`を上に置きます。右端のつまみをドラッグして任意の位置へ移動し、順番を保存します。ドラッグ中は青い挿入線を表示し、上下端で一覧がスクロールします。既存接続も直ちに再評価します。列見出しによる並べ替えは無効です。各行のCloneは元の直下にコピーを追加します。対象端末情報と曜日時間帯は独立したコピーとなり、一時許可の期限や監査履歴は複製しません。

**この版はサービス本体の更新が必要です。** 新EXEを起動し、「設定・サービス」で停止→「サービスのプログラムを更新」を実行します。旧サービスに接続中はルール変更を拒否して手順を表示します。新サービスは旧設定を読み込み、従来の明示拒否を優先して移行します。設定保存時は順序付き判定のスキーマ2となり、旧プログラムへの巻戻しで誤った許可をしないようにします。

6. LAN利用時はサービスを停止し、「初期設定・登録管理」で待受IPをループバックからLAN側の特定IPv4に変更・保存してから開始します。未登録時にもこの設定を保存できます。先に境界FWとWindows Firewallの送信元範囲を設定します。初期待受は **127.0.0.1:3128** です。

通常操作の「開始・停止・更新」は1行です。「更新」は状態表示の更新で、2秒ごとの自動更新も行います。稼働中は開始と運用設定、停止中は停止が無効になります。本体EXEの更新と登録削除は登録済み・停止中のときだけ、初期設定グループに表示します。画面下部の共通「再読込・検証・適用」ボタンはありません。

「サービスのプログラムを更新」は初回登録とは別の操作で、新しいEXEで登録先のプログラムを入れ替え、設定・ログを保持してサービスを開始します。通常の開始操作のたびに行う必要はありません。

サービスは初回登録時に **Windows起動時に自動開始** する設定になります。ログインやGUIの起動は不要です。「停止」は現在の稼働を止めるだけで、自動起動の設定は変更しません。したがって次のWindows再起動時には再び開始します。画面には、実際の登録設定を読み取って自動・手動・無効を表示します。

設定読込・待受開始が一時的に失敗した場合は、2・4・8・15・30・30・30秒の間隔で最大7回、約2分間再試行します。再試行中も管理GUIに接続でき、異常状態・次の再試行までの待ち時間・起動失敗と復旧の監査ログを確認できます。失敗した待受を破棄してから再作成します。設定破損・権限不足は自動再試行せず、時計やログの異常でも中止します。上限に達した場合は遮断状態を維持するため、診断情報を確認して原因を解消し、サービスを再起動してください。

初回登録・「サービスのプログラムを更新」時には、登録操作をしたWindowsユーザー向けにタスクスケジューラの `WhiteProxy Tray` を登録します。そのユーザーがログオンして約15秒後に、配置済みEXEを `--tray` で起動してトレイに常駐します。管理者権限の対話型タスクなので、登録済みの管理者アカウントではログオン時のUAC操作は不要です。GUI終了後も次回ログオンで起動し、サービス登録削除時にタスクも削除します。別のユーザーとして登録し直すと、トレイ起動の対象もそのユーザーに変わります。既存環境は新EXEで停止→「サービスのプログラムを更新」を行ってください。サービスはログオン前から動作しますが、トレイはログオン後に表示されます。

通信・監査ログの表は横罫線のみです。許可通信は淡い緑、拒否通信は淡い赤で表示し、結果欄を濃い色にしています。監査ログの結果・通信量等は「—」とし、通信の許可と区別します。宛先と理由の幅を確保し、画面に収まらない列は横スクロールで確認できます。

ダッシュボードは2秒ごとに状態を取得し、行構成が同じ場合は変更のあったセルだけを更新します。選択行・現在セル・スクロール位置を維持し、表のダブルバッファリングで更新時のちらつきを抑えます。

ログの「パス」列には、HTTP通信のパス（例 `/assets/logo.svg`）を許可・拒否・接続終了の各記録に表示します。パスでの検索、JSONL保存、CSV出力にも対応します。クエリとフラグメントを除き、エスケープ形式のまま最大2,048文字（超過分は末尾「…」）を記録します。HTTPS等のCONNECTトンネルはTLS非復号のためパスを取得できず「取得不可（CONNECT）」、旧版のログは「未記録」と表示します。過去のログにパスを後付けすることはできません。パスは診断用で、許可判定は引き続きホスト・ポート単位です。HTTPSの画像等のパスを調べるには、ブラウザー開発者ツールのNetworkタブを利用してください。

管理GUIは管理者、常駐サービス本体はNetworkServiceで実行します。同じEXEですが起動経路を分けており、サービスの自動起動時にUACを表示することはありません。設定変更IPCの管理者認可とデータ保存先のACLは維持しています。

サービス登録・開始時にWindows Firewallの受信許可を自動設定します。配置済みEXE・待受TCPポート・待受IP・登録端末のIPv4/CIDRに限定し、対象はDomain/Privateプロファイルです。ループバック待受や限定した送信元がない場合は外部向け許可を作りません。/0は自動許可から除外します。端末範囲の変更保存時も更新し、サービス登録削除時はアプリ管理のルールを削除します。手動作成ルールや他アプリのルールは変更しません。

既存環境は新GUIから停止→開始すれば自動設定を実行します。設定画面と操作結果に内容を表示します。組織ポリシー等による設定失敗は明示し、無制限な許可へ切り替えません。手動で管理する場合の補助スクリプトも残しています。

```powershell
./tools/Set-Firewall.ps1 -LocalAddress 192.168.10.10 -RemoteAddress 192.168.10.0/24 -Port 3128
```

開発時だけ、Visual Studioを終了してから「管理者として実行」で開き直し、「本体（要: Visual Studioを管理者として実行）」起動プロファイルを選択できます。プロファイル名だけでは昇格しません。未昇格でデバッグした場合は手順を表示して停止し、保存先のACLを変更しません。ビルド出力の `WhiteProxy.exe --console` を通常起動する場合はUACで昇格します。GUIとは別プロセスです。Windowsサービスと同時起動しないでください。デバッグ用EXEからのサービス登録は拒否し、単一ファイルの発行EXEを要求します。

## 検証範囲

Windows上のビルド、単一EXE発行・GUI起動、ポリシー境界、HTTP/HTTPS CONNECT、TLS非復号、強制切断、WebSocket、Range/206、長いHTTPストリーム、宛先IP保護、保存とNamed Pipe呼出者認可を自動テストしています。詳細は `docs/test-plan.md` を参照してください。

Windowsサービスの実登録・起動は本機で検証しています。**OS再起動、Windows Update/Defender、ChatGPT/Claude等のログインから実利用、複数GBダウンロードは実機受入確認が必要です。** 完全な接続先一覧や更新成功を保証していません。新規設定の初期サービスは添付定義を取り込んだWindows Updateの1件のみです。既存の保存済みサービスは更新時に上書きしません。端末・許可ルールは未登録のため、初期状態では通信は開放されません。

プロキシー非経由の直接通信・QUIC・DoH等は本アプリ単独では遮断できません。VLAN境界の出口制限が必要です。同じホスト内のURLは区別できず、患者情報等の外部送信を安全化するものでもありません。

## Webコントロール

「設定・サービス」のWebコントロールで、有効化・HTTPSポート（初期3129）・管理パスワードを設定できます。クライアントのブラウザーからダッシュボード、許可サービス、通信・監査ログを操作します。GUIと同じ検証・版管理を使用し、Webからの端末変更でもFirewallを再同期します。既存環境は新EXEから「停止」→「サービスのプログラムを更新」が必要です。自己署名証明書の信頼設定、接続範囲、操作手順は [Webコントロール](web-control.md) を参照してください。


## 許可サービスのインポートとGUI

「許可サービス」→「JSONからインポート」で、接続先をまとめたサービスセットを取り込めます。追加前にホスト・ポートを確認します。同一の定義はスキップし、同名で内容が異なる定義は別名で追加します。既存ルールの書換えや通信許可の作成は行いません。詳細な形式とOffice認証用の例は [サービスセット](service-packs/README.md) を参照してください。配布EXEは引き続き単一ファイルです。

管理GUIは同じWindowsセッションで一つだけ起動します。再度EXEを開くと既存画面を前面に戻し、最小化中なら復元します。サービス・コンソール本体・サービス管理コマンドはGUIの起動制限と分離しています。

ダッシュボードは縦罫線・操作列の見出しをなくし、状態バッジと淡い行背景、色分けした操作ボタンに変更しました。並べ替え用つまみは右端に置き、上下矢印ボタンは廃止しています。


## 拒否ログから許可先を選ぶ

「許可サービス」の追加/編集画面で「ログから候補抽出」を押し、端末IPv4（またはCIDR）と開始・終了日時を指定します。保存済みの拒否通信ログを検索し、ホストごとの回数・ポート・最初/最後の記録時刻・拒否理由を表示します。候補をチェックして編集欄へ戻し、親画面の「保存」で反映します。ポートやワイルドカードは自動で追加しません。直近1,000件の画面用ログだけでなく、保存ファイルを検索します。

ログ保持は初期値30日、1～365日で設定できます。「設定・サービス」でサービスを停止し、「待受IP・ポート・運用設定」→「ログ保持（日）」を変更してから開始します。日付と約10MiBでファイルを分割しますが、フォルダー全体の容量上限はありません。期間を過ぎたファイルはログ書込時に削除します。保存先は `%ProgramData%\WhiteProxy\logs` です。


許可サービスのJSONエクスポートは、一覧で対象を選び「選択サービスをJSONにエクスポート」から保存します。Ctrl/Shiftで複数選択できます。同じインポート形式で、サービス定義だけを共有・再取込できます。詳細は [サービスセット](service-packs/README.md) を参照してください。


## バージョンとルール編集

バージョン番号はルートの `Version.props` の `<Version>` に指定します。初期値は1.0.0です。変更してビルド/発行すると、EXE情報と管理GUIのタイトルに反映します。

ダッシュボードの既存ルールやCloneしたルールも、編集画面で許可サービスを変更できます。ルール位置・時間帯・手動遮断を維持します。旧サービスの有効な一時許可・予約がある場合は先にその枠を終了してください。同じ端末×サービスの重複を拒否し、一時許可を新しいサービスへ自動移行しません。
