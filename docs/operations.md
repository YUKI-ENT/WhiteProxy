# 運用手順

## 起動と登録

発行したWhiteProxy.exeを起動します。「設定・サービス」の「初期設定・登録管理」にある「初回登録して開始」を実行すると、UACの後、`%ProgramFiles%\WhiteProxy\WhiteProxy.exe` へコピーし、NetworkService、自動開始、障害時再起動のWindowsサービスを登録・開始します。GUIとのIPC接続まで確認してから完了します。Windowsサービス名は `WhiteProxy` です。ユーザーがGUIを起動していなくても動作します。

管理GUIは通常起動時にUACで昇格します。開始・停止・端末追加・ルール追加など、すべての管理操作を同じ管理者権限で行います。デバッグ時はVisual Studio自体を管理者として起動してください。デバッグ中の本体はWindowsサービスと同時起動しません。待受ポートだけでなくIPCの名前も排他的です。

GUI内の「管理者として開く」ボタンや閲覧専用モードは廃止しました。管理者権限を取得できなければGUIを開かず、取消または起動失敗を案内します。常駐サービスは引き続きNetworkServiceで動き、GUIの昇格とは別の実行経路です。サービスの実行アカウントやIPCの変更権限は緩めていません。

サービス操作欄には実際のSCM登録設定に基づく起動方法を表示します。自動の場合、Windows起動時にログイン・GUI起動なしでサービスが開始します。「停止」は今回の稼働だけを止め、自動起動の設定は変更しません。次のWindows再起動時には再び開始します。手動・無効・読取不可の場合は、その状態を明示し、自動開始するとは表示しません。

コンソールのデバッグはVisual Studio自体を「管理者として実行」で起動してください。起動プロファイル名は権限を付与しません。未昇格なら保存先のACL変更前に停止して案内します。EXEの `--console` 通常起動はUACで昇格します。以前の未昇格起動で `logs` 作成を拒否された場合も、既存のWhiteProxyフォルダーを削除したりUsersへ書込み権限を追加したりせず、昇格して再実行してください。

EXEの通常起動はGUIを開くだけです。サービス登録・開始時と登録端末IP/CIDRの変更保存時に、アプリ専用のFirewallルールを自動設定します。GUIを閉じる操作はプロキシー本体を停止しません。

## トレイ常駐とアイコン

白い中継ゲートを表した共通アイコンを、EXE・管理画面・各編集画面に設定しています。サービス登録後はGUIをトレイに常駐させ、サービス停止中も残します。×ボタンまたは最小化で画面を隠し、ダブルクリックまたは右クリックの「管理画面を開く」で戻ります。EXEを再度開いた場合も既存画面を復元します。

- 緑の再生マーク：サービス稼働・管理GUI接続済み・正常。
- 灰色の停止マーク：Windowsサービス停止中。
- 黄色の注意マーク：起動/停止処理中、状態不明、GUI未接続、異常、旧サービス、または全遮断。マウスを合わせると理由を表示します。

約2秒ごとに状態を更新します。右クリックの「設定・サービス」から操作画面へ移動できます。「GUIを終了（サービスは継続）」はGUIだけを終了します。未登録では×で終了し、登録を削除した場合はトレイを消して隠れていた画面を再表示します。Windowsのシャットダウン・サインアウトは妨げません。

トレイはGUIを起動したログインセッションに表示します。WindowsサービスはGUIやログインの有無とは独立して稼働します。

## 設定

1. 「許可サービス」で完全一致ホスト・サブドメインパターンとTCPポートを登録します。組込候補をコピーして独自定義にもできます。空のホスト一覧は一切許可しません。
2. ダッシュボードの「許可ルールを追加」で、登録済み端末を選ぶか、新しい端末名とIPv4/CIDRを直接入力します。CIDR範囲は保存時に確認し、IP/CIDRは同一・重複範囲を指定できます。端末とルールを同時保存し、キャンセル時の部分保存はしません。
3. 許可サービスを明示的に選択し、通常の許可時間を指定します。初期値の「一時許可のみ」は保存だけでは通信を許可しません。「全日・24時間」は常時許可の確認を出します。「曜日・時間帯」は複数枠を指定でき、次回予定を表示します。曜日は月火水木金土日の横並びです。「毎日・平日・土日・リセット」で選択できます。新しく指定する時間帯は同日の開始より後の終了時刻が必要です。既存の日跨ぎ設定は保持しますが、時間帯を編集する場合は同日の枠へ変更してください。
4. 各編集画面の「保存」で検証・原子的保存・接続の再評価まで実行します。エラーの場合は画面を閉じず入力を残します。曜日別予定表の子画面は「決定」で親画面へ戻り、親の「保存」で反映します。共通の検証・適用ボタンはありません。
5. 対象の端末名・IPv4/CIDRはルール編集画面で直接編集できます。同じ端末を複数ルールで選択している場合、その対象情報を共有する旨を表示します。「端末の状態」行や別の情報編集ボタンはありません。

端末管理・スケジュール用の独立タブはありません。ダッシュボードは、状態・端末/IP・サービス・通常の許可時間・現在の理由を表示し、その右に各行の「編集・一時許可・一時遮断・削除・Clone」ボタンを置きます。期限/予約/次回開始の独立した列は廃止し、必要な期限は一時許可フォームで確認します。緑は許可時間枠、赤は遮断中です。サービス未接続・停止・異常時は灰色の「状態未確認」にします。

ルールは上から順に送信元IP/CIDRと接続先ホスト・ポートのサービスを照合し、基本は拒否です。時間外・一時許可期限切れ・開始予約・端末停止/無効の行は読み飛ばし、最初に一致する有効な許可または明示的な手動遮断で判定を確定します。有効な許可がなければ拒否します。同じ端末に複数のサービスを設定できます。全遮断と一致する無効サービスは優先して拒否します。/24の遮断の例外として/32を許可する場合、/32を上に置きます。右端のつまみをドラッグすると青い挿入線の位置へ移動できます。端までドラッグすると自動スクロールします。上下の行間、先頭、末尾へ移動でき、自分自身の位置や一覧外へのドロップ・Escによるキャンセルは保存しません。上下矢印ボタンは廃止し、つまみに統一しています。移動先の順序を即時保存し、既存接続を再評価します。Cloneは元の直下へ、同じIP/CIDR・サービス・通常の許可時間・手動遮断設定のコピーを追加します。対象端末と時間帯は独立して編集でき、コピー側を変えても元のルールに影響しません。サービス定義は共通です。一時許可の期限・予約・監査主体は複製しません。元のルールが有効な許可または明示的な遮断の場合は先に適用されるため、コピーを例外として使う場合は編集後に上へ動かします。

ルール編集で順番を末尾へ移しません。列見出しのソートは無効です。全遮断と無効な宛先サービス、接続先IPの安全確認は引き続き優先します。

同じサービスで上位のCIDRに全体が含まれる下位ルールは、上位に有効な許可または明示的な遮断がある場合は、その判定結果と適用行番号を表示します。時間外の上位行は影響しません。範囲の一部だけが重なる場合、理由欄に「一部は上位優先」と表示します。色は範囲内の全通信や宛先の到達性の保証ではありません。

別GUIで設定が変更された場合は版競合として拒否します。その場合は編集画面を開き直して最新の設定から編集してください。画面表示は2秒ごとに自動更新し、手動の「更新」はサービス操作の行にあります。

サービス操作は「開始・停止・更新」を1行に配置しています。開始は稼働中、停止は停止中、運用設定は稼働中・起動/停止処理中に無効です。操作を実行している間は別のサービス操作も無効です。ボタンの文字と状態表示に加え、開始は緑、停止は赤、更新は青、無効な操作は灰色で表示します。

待受IP・ポート・タイムゾーン・運用上限は「初期設定・登録管理」にまとめています。未登録または停止中に管理者GUIで保存でき、次回開始時に反映します。既存の端末・許可ルール・一時許可履歴・全遮断状態は保持します。保存直前にもサービス停止状態と設定版を確認し、稼働中や版競合では書き込みません。

## 一時開放と緊急遮断

各行の「一時許可」フォームで横並びのトグルボタンから新規・変更/延長・終了を選択します。対象端末・サービス・現在の有効期限を表示します。理由の入力は不要です。30分/1/2/4時間ボタン（設定上限内だけ表示）、または終了日時を直接指定できます。開始予約もできます。表示は設定タイムゾーン、保存はUTCです。初期上限は今から4時間、設定で最大24時間。重複時は既存枠を監査用に取消して新しい枠へ統合します。既存期限より短縮する操作は拒否します。旧設定でルールがなく一時許可だけ存在する端末×サービスも一覧に表示します。

同じフォームの「一時許可・予約を終了する」は、そのルールの有効な一時許可・予約を取消します。他の予定表や常時許可があれば通信は継続します。一時許可が残るルールは削除できず、先に一時許可の終了が必要です。

各行の「一時遮断」フォームで横並びのトグルボタンから遮断・解除を選択します。遮断は解除するまで継続します。既存のDeny設定を使用し、この行の予定表・常時許可・一時許可より優先します。上位の有効な許可が先に一致する場合は上位を適用します。「遮断を解除」は元のスケジュールと、有効期限内の一時許可へ戻す操作です。時間外や期限切れなら下位のルールも確認し、有効な許可がなければ拒否します。編集画面には「明示拒否」チェックを表示しません。従来の明示拒否は手動遮断として維持し、ルールを保存しても勝手に解除しません。遮断中でも有効な一時許可が残る場合は、同じ一時許可フォームから終了できます。遮断中の新規許可・延長はできません。手動遮断ルールの削除時は、遮断解除と重複する許可先への影響を確認します。

「すべて遮断」は全ルールより優先し、既存接続も終了します。解除は管理者の明示操作のみです。

Windows Updateを1回だけ開放する操作は「指定した1つの時間枠」の意味です。更新の完了検出は行いません。期限になれば途中のダウンロードも切断します。

## 保存・バックアップ

保存先 `%ProgramData%\WhiteProxy\`:

| ファイル | 用途 |
|---|---|
| configuration.json | スキーマ2（順序付きルール）の現行設定 |
| configuration.json.bak | 直前の設定。自動復旧はしない |
| last-clock-utc.txt | 時計巻戻し検出用の最終UTC |
| service-status.json | 起動段階・エラーの診断情報のみ。一般ユーザーは読取り可 |
| runtime/ | サービスの単一EXEのネイティブランタイム展開先（通信キャッシュではない） |
| logs/YYYYMMDD-NNNN.jsonl | UTF-8通信・監査ログ |

管理者、SYSTEM、NetworkServiceだけが書込み可能です。バックアップは設定とログを管理者が保管します。一般ユーザーによるファイル直接編集は想定しません。

設定破損・外部変更・ファイルアクセス失敗時は通信を遮断します。GUIが接続できる場合は編集・検証・再適用してください。ファイル復旧が必要な場合はサービス停止後に `.bak` の内容とUTC期限を確認し、管理者が明示的に現行設定へ戻してから起動します。再起動時にも一時許可は現在UTCで評価され、失効済み枠は復活しません。

## 時計・ログの異常

時計異常とログ欠損は一度起きると自動で開放しません。OS時刻/NTP、空き容量、ACLを確認してサービスを再起動します。時計マーカー自体が壊れている場合は、停止中に正しいUTCと履歴を確認して管理者が修復します。ログの壊れた行は退避して原因を調査してください。

ログキュー溢れ・書込み失敗は欠損数とエラー状態で表示します。GUIの通信ログは直近1,000件です。端末/ホスト/サービスID/理由・許可拒否・期間で絞り込み、表示結果をCSVに出力できます。長期間の調査はJSONLを使います。CSVの数式開始文字は無害化します。

## 更新・削除

この版はサービス本体の更新が必要です。新GUIは旧サービスの応答を識別し、ルールの変更や一時許可を無効にして更新手順を表示します。スキーマ1は読込時に従来の明示拒否を前に並べて移行し、保存時にスキーマ2へ更新します。一時許可・失効期限・監査履歴は保持します。旧EXEはスキーマ2を拒否するため、旧方式で順序を無視して動作しません。

本体更新はサービスを停止してから、新しい発行EXEの管理者用初期設定グループにある「サービスのプログラムを更新」で実行します。初回登録とは違い、新しいEXEを登録先へコピーしてサービスを開始する操作です。設定・ログは保持し、通常の起動のたびに更新する必要はありません。初回登録は未登録時だけ、プログラム更新・登録削除は登録済み・停止中だけ表示します。通常行の「更新」は画面の状態更新であり、本体の入替は行いません。デバッグ用の複数ファイルEXEは登録できません。Program Filesにある稼働EXEを直接上書きせず、別フォルダーの新EXEから更新してください。

状態欄にはSCMの登録状態、実行ファイル、実行アカウント、GUI接続状態、直近の起動段階とエラーを表示します。「サービスに接続」とだけ表示して操作を繰り返させる挙動は修正しました。

「サービス登録を削除」は停止を待ってからSCM登録を削除します。設定とログ、Program FilesのEXEは保持します。必要なら管理者が別途削除します。自動管理のFirewallルール `WhiteProxy-Managed-Inbound` はサービス登録削除時に削除します。補助スクリプトで手動作成した `WhiteProxy-Scoped-Inbound` は自動管理の対象外なので、運用終了時に管理者が別途削除します。


ドラッグ・Clone・トグルの追加はGUI側の変更です。前の順序付きルール対応版へサービスを更新済みなら、新しいGUIの起動だけで利用できます。旧サービスの場合は引き続き更新手順を表示します。


## 外部サービスセットのインポート

「許可サービス」の「JSONからインポート」でUTF-8のサービスセットを選択します。追加前の確認画面でホスト・TCPポート・出典を確認し、「追加する」でサービス定義だけを保存します。既存サービスを上書きせず、同じ定義はスキップします。同名で内容が違う場合は別名で追加します。インポートしたサービスをダッシュボードのルールで指定するまで、新しい通信許可は作成されません。形式と例は [サービスセット](service-packs/README.md) を参照してください。保存後の運用に元JSONを置き続ける必要はありません。

## 管理GUIの起動と表示

管理GUIを再起動・更新する場合は、トレイを右クリックして「GUIを終了（サービスは継続）」を選んでから新EXEを開きます。登録済みでは×ボタンは終了ではなくトレイ格納です。二度目の起動は既存画面の復元・前面表示になります。同時起動競合は名前付きMutexで防ぎます。GUIが異常終了した後も起動でき、Windowsサービスの自動起動・管理コマンドはGUIのMutexに関係なく動作します。

表は横の区切り線だけを使用し、操作ボタン列の見出しを表示しません。状態は緑/赤のバッジ、行全体は淡い背景、選択行は淡い青です。編集は青、一時許可は緑、一時遮断は橙、削除は赤、Cloneは紫のボタンです。操作不能なボタンは灰色にします。


## ログから候補抽出

1. 「許可サービス」で対象のサービスを追加/編集し、ホスト入力欄の下の「ログから候補抽出」を開きます。
2. 対象の端末IPv4またはCIDRを指定します。空欄では全端末を検索します。開始・終了日時は設定タイムゾーンで入力し、開始以上・終了未満のUTC範囲へ変換します。初期範囲は直近1時間です。
3. 「候補を検索」で保存済みのJSONLを読み込みます。サービスの直近1,000件のメモリ上ログに限定しません。通信種別の拒否ログだけから完全一致ホストを集計し、回数・ポート・最初/最後の時刻・拒否理由を表示します。IP表記がIPv4-mappedの場合もIPv4フィルタに一致します。
4. 必要なホストをチェックし「選択したホストを追加」で親の編集欄へ戻します。初期状態は全件未チェックです。既存ホストや既存ワイルドカードでカバー済みの候補は「登録済み」とし、重複追加しません。TCPポートは参考表示だけで、親画面の許可ポートを変えません。
5. 親画面の「保存」で初めて検証・反映します。親をキャンセルすれば追加しません。別アプリやバックグラウンド通信もログに混ざるため、該当操作の必須ホストであることをログだけでは保証しません。候補を選んでもワイルドカードへ広げません。

書込中のログは読取開始時点の長さまで読みます。末尾の書込途中行や不正行、読めなかったファイルは件数を表示します。1回の検索は256MiB・2,000候補ホストを上限とし、上限到達時は部分結果と明示します。30秒経過または中止ボタンで検索を中止できます。期間・端末を絞って再検索してください。この上限は検索処理の上限で、保存ログの総容量上限ではありません。

## ログの保存期間・容量

初期保持日数は30日、設定範囲は1～365日です。「設定・サービス」→「停止」→「待受IP・ポート・運用設定」→「ログ保持（日）」で保存し、サービスを開始します。設定・サービスの画面下にも保持日数・分割サイズ・総容量制限の有無・保存先を表示します。未接続時は現在値を取得済みと誤表示しません。

保存先は `%ProgramData%\WhiteProxy\logs`。UTCの日付ごと、または1ファイル約10MiBに達したときに分割し、ログ追記時に最終更新時刻が保持日数より古いJSONLを削除します。書込みがなければ削除処理もその間は走りません。総容量を指定する設定はなく、保持期間内の通信量に応じて増加します。サイズ分割は総容量制限ではありません。

候補抽出は管理GUIが管理者権限で保存ログを読取専用で検索する機能です。サービスのIPCや設定形式の変更はないため、順序付きルール対応のサービスを更新済みなら今回の変更での本体更新は不要です。


新規の一時許可の終了時刻は、設定の「一時許可上限（時）」を初期時間として使用します（初期設定4時間）。既存の一時許可・予約を開いた場合は、保存済みの終了時刻と予約開始時刻を維持します。


## Windows Firewallの自動設定

サービスの登録・開始操作で、保存済み設定に基づいて `WhiteProxy-Managed-Inbound` 受信許可を作成/更新します。配置済みProgram FilesのWhiteProxy.exe、TCPの待受ポート、特定の待受IPv4（0.0.0.0の場合は全ローカルIPv4）、有効な登録端末の送信元IPv4/CIDRを指定します。Publicへは許可せず、Domain/Privateのみ、Edge Traversalは無効です。

初回のループバック待受や登録端末なしでは外部向け許可を作りません。/0とループバック送信元は自動許可から除外し、その結果を表示します。後でLAN待受と端末を設定し、サービスを開始すると適切な範囲で作成します。端末範囲が変わる設定保存時は再設定します。単なるサービス名・ホスト定義・ルール時間の編集ではFirewallを書き換えません。

アプリ管理ルールだけを作り直し、削除後の追加に失敗した場合は広い旧ルールへ戻しません。Firewallの失敗時は登録/開始操作を中止して原因を表示します。プロキシー設定の保存後にFirewall更新が失敗した場合は、設定は保存済みであることを明示します。サービス停止→開始で再設定できます。既存の手動ルールや他アプリのルールは維持し、Firewall自体の有効/無効や組織ポリシーも変更しません。別の受信許可が存在する場合、それによる通過まで制限するものではありません。

## ルールのサービス変更とバージョン

ルール編集の「許可サービス」は既存ルールでも選択できます。保存時に変更を確認し、元の行位置・通常の許可時間・手動遮断を引き継ぎます。旧サービスの一時許可/予約が残る場合は先にダッシュボードの一時許可フォームから終了してください。履歴は維持します。同じ端末と変更先サービスのルールが既にある場合は重複として拒否します。Cloneは対象端末IDが独立しているため、コピー後にサービスやIPを変更できます。

表示バージョンはルートの `Version.props` の `<Version>1.0.0</Version>` で管理します。変更してVisual Studioでビルド/発行してください。管理GUIのウィンドウタイトルとEXEのバージョン情報へ反映します。バージョン違いのGUIを開いた場合も、既存ウィンドウの前面表示と単一起動制御を維持します。


## 待受IPと接続元範囲の違い

待受IPv4は、プロキシーを実行するPC自身に割り当てられたIPです。LANのクライアント側IPやネットワーク範囲を指定する欄ではありません。例えばこのPCの割当が192.168.200.111/24なら、特定NICの待受には192.168.200.111を選びます。全NICの待受を明示的に選ぶ場合は0.0.0.0です。接続元端末の範囲は、許可ルールの端末IPv4/CIDR欄で指定します。

192.168.0.0等がこのPCに割り当てられていなければ待受できません。.0で終わるアドレス自体を一律禁止するのではなく、実際の割当アドレスと照合します（/23等では末尾.0がホストになる場合があります）。GUI保存時・保存直前・本体の起動時に確認し、DHCP変更等で割当が失われた場合も明確なメッセージを表示します。ライブラリが包んだソケット例外も、IP未割当とポート使用中を区別して案内します。


待受先は手入力を廃止し、このPCの有効なNICに割り当てられたIPv4をNIC名付きで一覧表示します。「このPC内だけで利用 — 127.0.0.1」と「すべてのNICで待受 — 0.0.0.0」も明示的に選択できます。接続元端末の/16等の範囲は、引き続き許可ルール側のIPv4/CIDRで設定します。

保存済みIPが現在見つからない場合は「現在は未割当の保存値」として表示し、自動で別NICや全NICへ切り替えません。利用者が候補を選び直すまで保存を拒否します。保存するのはIPそのものだけで、画面のNIC名や説明文は設定値へ入りません。保存前の最新の割当照合も維持します。


### リモートアドレスの決定とFirewall画面

リモートアドレスはConfiguration.Devicesに残っている「有効な端末」のIPv4/CIDRから作成します。ルール作成・Clone時に端末情報が登録されます。IPはネットワーク境界に正規化し、完全に同じ範囲は重複を除きます。ループバックと全IPv4の/0は除外します。時間帯・一時許可・手動遮断の状態ではFirewallの範囲を変更しません。

初回で端末が一件もなければ、外部向けの管理受信ルールは作成しません。一度作成した許可ルールをすべて削除しても端末情報は残るため、そのIP/CIDRがFirewallに残る場合があります。有効な許可がなければプロキシーの判定で通信を拒否します。Firewallは入口のIP/ポート、アプリは宛先・時間帯等を判定する構成です。待受がループバックの場合は端末登録にかかわらず外部向け許可を作りません。

「設定・サービス」の操作行に「Windows Firewallを開く」を追加しました。詳細設定付きWindows Defenderファイアウォールを開きます。「受信の規則」→「WhiteProxy-Managed-Inbound」→「スコープ」で実際の送信元範囲を確認できます。管理画面を開くだけで、アプリの設定やFirewallルールは変更しません。
