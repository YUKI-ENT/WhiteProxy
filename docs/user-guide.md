# WhiteProxy 導入・操作ガイド

閉鎖ネットワークの端末から、Windows Updateなど必要なインターネット接続だけを利用するための手順です。

## 1. 院内VLAN構成例と配置

以下のようなVLAN構成を例にとって説明します。各施設の状況に合わせて読み替えて下さい。

WhiteProxyを動かすWindows PCを、**VLAN1（インターネット可能ゾーン）** に置きます。VLAN2（閉鎖電子カルテゾーン）の端末は、ルーターを経由してこのPCに接続します。

![VLAN1とVLAN2を分けた院内ネットワーク図。VLAN2の端末からルーターを経由してVLAN1のWhiteProxyへ接続する。](images/network-overview.png)

**オレンジの矢印**は端末からルーターを経由してWhiteProxyへ接続する流れ、**緑の矢印**はWhiteProxyからルーターを経由してインターネットへ接続する流れです。応答方向の矢印は省略しています。

| 項目 | このガイドの例 |
| --- | --- |
| VLAN1 | `192.168.10.0/24`、ルーター `192.168.10.1` |
| VLAN2 | `192.168.20.0/24`、ルーター `192.168.20.1` |
| WhiteProxy用PC | 固定IP `192.168.10.10`、ゲートウェイ `192.168.10.1` |
| 利用端末 | `192.168.20.21`、ゲートウェイ `192.168.20.1` |
| Web管理端末 | `192.168.20.50`、ゲートウェイ `192.168.20.1` |
| プロキシー接続先 | `192.168.10.10:3128` |
| 管理画面URL | `https://192.168.10.10:3129/` |

IPアドレスは院内の実際の値に置き換えてください。WhiteProxy用PCにはインターネットへの通信とDNSによる名前解決が必要です。VLAN2内の電子カルテやDNSなどは、既存の院内構成を維持します。

通信の流れは **利用端末 → WhiteProxy → 許可したインターネット上の接続先** です。VLAN2からインターネットへ直接出る経路はルーターで遮断します。

## 2. VLAN間通信の許可

閉鎖電子カルテゾーン(VLAN2とします)からインターネット可能ゾーン(VLAN1とします)への **TCP3128と3129(Web管理機能を利用する場合のみ)** のVLAN間通信を許可して下さい。

このあたりは、
```
外部と遮断された閉鎖VLAN（192.168.x.x/24）内のPC(192.168.x.10,192.168.x.11,192.168.x.12)から
インターネット接続のあるVLAN内のPC（192.168.y.10）にTCP3128を許可するルーター設定を教えて
```
ようにAIに聞いていただいたほうがわかりやすいと思いますが、RTX830での設定例を例示しておきます。

### RTX830のVLAN間通信設定例

| 接続元 | 接続先 | 許可する通信 |
| --- | --- | --- |
| VLAN2の利用端末 | WhiteProxy用PC `192.168.10.10` | TCP 3128（プロキシー） |
| Web管理端末 `192.168.10.50`| 同じPC | TCP 3129（Web管理を使う場合） |
| WhiteProxy用PC | 上記VLAN2内端末 | 上記通信への応答（動的フィルターで自動許可） |
| VLAN2 | その他のVLAN・インターネット | 原則遮断。既存業務に必要な通信は個別に許可 |

### フィルター設定例（動的フィルター）

次は、VLANが設定済みで、VLAN2のインターフェース名が **`lan1/1`** の場合のIPv4設定例です。`lan1/1` はヤマハのインターフェース名で、VLAN番号の「1」を意味するものではありません。実機のVLAN2が `vlan2` などの場合は読み替えます。

**VLAN2から許可した接続を開始すると、その接続の戻り通信も自動的に通します。** WhiteProxy側からVLAN2へ別の接続を開始することは許可しません。静的フィルターで接続先を絞り、動的フィルターで接続状態を追跡します。

**既存設定をバックアップし、管理接続を復旧できる状態で作業してください。** 下の適用コマンドは、そのインターフェースの既存フィルター一覧を置き換えます。稼働中の院内ルーターへそのまま投入せず、DNS・DHCP・時刻同期・別VLANの業務サーバー・ルーター管理など、必要な既存許可を残して組み込みます。フィルター番号も未使用のものに変更してください。

```text
# 静的フィルター：VLAN2から開始できる接続先を限定
ip filter 210100 pass 192.168.20.0/24 192.168.10.10 tcp * 3128
ip filter 210110 pass 192.168.20.50 192.168.10.10 tcp * 3129
# これ以外のVLAN2からのルーティング通信を拒否
ip filter 210199 reject * * * * *

# 動的フィルター：上記のTCPポートへの接続と、その戻りを追跡
ip filter dynamic 210300 192.168.20.0/24 192.168.10.10 filter 210100
ip filter dynamic 210310 192.168.20.50 192.168.10.10 filter 210110

# VLAN2への新規接続は拒否（追跡済みの戻り通信は動的フィルターで通過）
ip filter 210299 reject * * * * *

# VLAN2側インターフェースに適用（既存の必要な許可も一覧に含める）
ip lan1/1 secure filter in 210100 210110 210199 dynamic 210300 210310
ip lan1/1 secure filter out 210299
```

`in` はVLAN2からルーターへ入る通信、`out` はルーターからVLAN2へ出る通信です。接続を開始する `in` 側に動的フィルターを適用すると、対応する戻り通信は `out` 側の拒否規則より優先して通ります。戻り用の `established` 許可規則は不要です。動的フィルターだけでは不要な通信を拒否できないため、静的な許可・拒否規則も残します。

動的フィルターの `filter 210100`／`filter 210110` は、参照先のTCP・ポート条件を使います。参照先のIP条件は動的フィルターでは使われないため、`ip filter dynamic` 自体にも接続元・接続先IPを指定しています。Web管理を使わない場合は静的規則 `210110`、動的規則 `210310` と、`in` の適用一覧の対応番号を省きます。

VLAN1側にもフィルターがある場合は、そのインターフェースでも必要な往復通信を通す設定が必要です。この例の動的フィルターはVLAN2側に適用するもので、別のインターフェースの遮断設定まで解除するものではありません。仕様は [ヤマハ公式：動的フィルターの定義](https://www.rtpro.yamaha.co.jp/RT/manual/rt-common/ip/ip_filter_dynamic.html)、[動的フィルターの動作と適用例](https://www.rtpro.yamaha.co.jp/RT/docs/firewall/index.html)、[適用方向と評価順](https://www.rtpro.yamaha.co.jp/RT/manual/rt-common/ip/ip_interface_secure_filter.html) を参照してください。

WAN接続・NAT・VLAN自体の作成は既存構成に合わせます。タグVLANの説明は [ヤマハ公式：VLAN](https://www.rtpro.yamaha.co.jp/RT/docs/vlan/) にあります。

確認が済んだらRTX830の設定を保存します。ルーターに許可を追加するだけではWhiteProxyの通信は開通せず、以降の端末・ルール登録も必要です。この例の実機投入前には、既存業務の通信も含めて接続確認を行ってください。

## 3. WhiteProxyのインストール

1. 配布された `WhiteProxy.exe` をWhiteProxy用PCにコピーして起動します。
2. WhiteProxyは**管理者権限のアカウントでしかインストールできません**。標準ユーザーではインストールできません。
3. 「設定・サービス」を開きます。初回の「サービス未接続」は正常です。

4. 「初期設定・登録管理」の「待受IP・ポート・運用設定」を開き、待受IPを **このPCの `192.168.10.10`**、ポートを **3128** にして保存します。

   <img width="666" height="673" alt="スクリーンショット 2026-10-30 170349" src="https://github.com/user-attachments/assets/5a17d13e-8df1-4085-b98d-b9b37785746e" />


    初期待受は `127.0.0.1` で、そのPC自身からしか接続できません。変更することにより、選択したNIC、あるいは全NICで待ち受けるようになります。

### 接続確認と端末側の設定

手順6で端末を登録した後、利用端末でPowerShellを開き、次を実行します。

```powershell
Test-NetConnection 192.168.10.10 -Port 3128
```

`TcpTestSucceeded : True` が目安です。これはポートへの到達確認なので、Webサイトの許可は別途ルールで確認します。

利用端末のWindows「設定」→「ネットワークとインターネット」→「プロキシ」で、手動プロキシを `192.168.10.10`、ポート `3128` に設定します。院内の電子カルテなど、直接接続する宛先は組織の既存の除外設定を維持してください。

Windows Updateにはブラウザー用とは別のプロキシー設定が必要な場合があります。[端末・Windows Updateの設定](client-setup.md) を確認してください。

### バージョンアップ等でプログラムを更新する場合

旧GUIをトレイの「GUIを終了」で終了し、新しいEXEを開きます。「設定・サービス」で **停止 →「サービスのプログラムを更新」** を実行します。設定・ログは保持されます。更新に伴い通信はいったん切断されます。

## 5. 許可サービス（サイトリスト）の追加

「許可サービス」は、接続先ホストを用途ごとにまとめたものです。本ソフトでは、**許可サービスの設定 → 各端末ごとにどのサービスをいつ許可するかのルールを作成**、という流れになります。

初期登録は **Windows Updateの1件** です。既存環境を更新した場合は、保存済みのサービスが維持されます。

1. 「許可サービス」タブで追加操作を選びます。

2. 分かりやすいサービス名を入力します。ここでは薬剤検索等を行うために**PMDAのサイトを追加する例**を示します。

3. 「ホスト（1行1件）」に接続先を入力します。Enterキーで次の行へ進めます。

    <img width="666" height="793" alt="スクリーンショット 2026-10-30 182042" src="https://github.com/user-attachments/assets/56454f67-310b-4af7-931b-1eff99d35698" />

4. 「許可TCPポート」は、通常のWeb利用なら `80,443` にします。

`example.com` はそのホストだけ、`*.example.com` はサブドメインだけに一致します。**親ホストも使う場合は両方を登録します。** `https://` や `/assets/logo.png` などのパスは入力しません。

画像やログイン先が別ホストの場合は、そのホストも必要です。まず利用を試し、拒否ログから不足する接続先を確認します。GUIのサービス編集では「ログから候補抽出」も利用できます。JSONファイルがある場合は「JSONからインポート」で取り込めます。

### 日常の操作

| やりたいこと | 操作 |
| --- | --- |
| 今だけ接続する | 行の「一時許可」で終了時刻を指定 |
| 決まった曜日・時間に接続する | 行の「編集」→「曜日・時間帯を指定」 |
| 常に接続する | 行の「編集」→「全日・24時間（常時許可）」 |
| 一時許可を早く終了する | 「一時許可」の終了操作を選ぶ |
| そのルールを止める | 行の「一時遮断」。再開は遮断解除 |
| 全体を緊急停止する | 緊急操作の「すべて遮断」。復帰は「全遮断を解除」 |

一時許可の期限が切れると、ほかに有効な許可がなければ通信は遮断され、接続中の通信も切断されます。常時許可や曜日設定がある場合、一時許可の終了だけでは遮断されません。停止したい場合は「一時遮断」を使います。遮断解除は、元の予定や有効な一時許可へ戻す操作です。

範囲が重なるルールは上から判定されます。時間外のルールは次へ進み、最初の有効な許可または明示的な一時遮断が適用されます。GUIでは右端のつまみをドラッグ、Webでは上下ボタンで順序を変更します。最初は対象範囲の重複を避けると管理しやすくなります。

### ログを見る

「通信・監査ログ」を開き、端末IP・接続先ホスト・時刻・理由を確認します。許可は淡い緑、拒否は淡い赤です。設定変更などは監査ログに残ります。

| 表示・症状 | 確認すること |
| --- | --- |
| 未登録端末 | 端末の実際のIPがルールの対象に含まれるか |
| 未許可ホスト・ポート | 必要な接続先がサービスに登録されているか |
| 時間外・許可なし | 一時許可の期限や曜日設定が有効か |
| 手動遮断・全遮断 | 遮断が解除されているか |
| ログ自体が出ない | 端末のプロキシー設定、ルーター、Windows Firewall |

HTTP通信は「パス」も確認できます。HTTPS通信は暗号を復号しないため、ホストは分かりますがパスは「取得不可（CONNECT）」です。画像などの詳しいURLは、ブラウザーの開発者ツールのNetwork欄で確認します。

## 7. Webコントロール

管理端末のブラウザーから、ダッシュボード・許可サービス・ログを操作できます。プロキシー用3128とは別の **HTTPS 3129** を使います。

### 有効にする

1. WhiteProxy用PCで「設定・サービス」→「Webコントロール（HTTPS）」を開きます。
2. 「Webコントロールを有効」にチェックします。
3. ポート `3129` とパスワード（5文字以上）を入力し、**「Web設定を保存」** を押します。保存時に自動のWindows Firewall規則を設定します。
4. 「公開証明書を書き出す」で `.cer` ファイルを保存します。

### 別VLANから管理する場合のFirewall設定

自動のWeb用受信許可は **ローカルサブネットのみ** です。この例のVLAN2の管理端末から接続するには、手順2のルーター設定に加えて、WhiteProxy用PCで管理端末のIPを明示したWindows Firewall規則を用意します。

Windowsの「セキュリティが強化されたWindows Defenderファイアウォール」で、受信規則を次の内容で追加します。

| 項目 | 設定例 |
| --- | --- |
| 名前 | `WhiteProxy-Web-Control-VLAN2-Admin`（手動管理用） |
| 規則の種類 | カスタム |
| プログラム | `C:\Program Files\WhiteProxy\WhiteProxy.exe` |
| プロトコル／ローカルポート | TCP / 3129 |
| ローカルIP | `192.168.10.10` |
| リモートIP（接続元） | 管理端末 `192.168.20.50` |
| 操作／プロファイル | 接続を許可／ドメイン・プライベート |

この手動規則はアプリの自動削除対象ではありません。Web管理の廃止・ポート変更時には担当者が削除・修正します。

### 証明書を登録してログインする

1. `.cer` をブラウザーを使う管理端末へ渡し、サーバー画面にある証明書のSHA-256指紋と照合します。
2. `.cer` を開き「証明書のインストール」を選びます。
3. **「ローカルコンピューター」** を選び、管理者確認を許可します。
4. 「証明書をすべて次のストアに配置する」→ **「信頼されたルート証明機関」** を選んで登録します。
5. ブラウザーをすべて終了して起動し直します。
6. `https://192.168.10.10:3129/` を開き、設定したパスワードでログインします。

ブラウザーにプロキシーを設定している場合は、管理先 `192.168.10.10` をプロキシーの除外一覧へ追加し、直接接続します。証明書に含まれるIPまたはPC名でアクセスしてください。証明書作成後にサーバーのIPが変わった場合は再確認が必要です。

ログインは24時間有効です。ログアウト、Web設定の変更、サービス再起動時は再ログインします。Windowsサービスの開始・停止・本体更新、プロキシーの待受設定はサーバー側のGUIで行います。

詳しい手順や証明書の更新は [Webコントロールの詳細](web-control.md) を参照してください。

WhiteProxyは許可する接続先と時間を管理します。プロキシーを使わない通信の遮断はルーターで行います。外部サイトへの患者情報・機密情報の入力可否は、院内の運用ルールに従ってください。
